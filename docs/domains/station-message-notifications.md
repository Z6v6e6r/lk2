# Station message notification bridge

Concrete, default-off source path: LK committed contiguous publication feed → PostgreSQL fact/fanout/recipient outbox → generic inbox and guarded APNs/FCM/Web Push. It does not project or own chat membership. User-visible text never contains message text, private owner IDs or author identity; `/notifications` is the fixed link. Historical generic inbox may remain; actual chat access independently checks current ACL.

`STATION_NOTIFICATIONS_ENABLED` is owned by the notification/release owner. It requires the dedicated fixed HTTPS origin, canonical tenant, issuer/audience/kid and mounted JSON `{privateKey}` file. No key creation or installation is part of development. Three read-only owner POSTs use a dedicated <=30s JWT and bounded responses. Candidate audience is current unread ACTIVE members, excluding author; projection and each send recheck the original epoch/baseline. An absent/changed/deleted source is unavailable, not DENY or an invented empty audience. The paired LK feed/CUP type-floor correction must be installed and verified before activation.

Input must include approved original community mapping, incarnation/stream and replay floor. Never infer floor0 from absence or reset an old source. Retain source/outbox/receipt rows on rollback.

The importer persists a fixed frontier and only advances after immutable facts commit. Every remaining identity-lock wait precedes fresh policy/DB-clock and owner-budget checks. Locks are released before provider calls. Generic Rabbit source publication is deliberately absent: recipient work and inbox/push/audit outbox commit in one PostgreSQL transaction. Broker/queue absence cannot erase recipient work. Missing provisioning/runtime holds before projection; user preference/quiet rules suppress according to existing nonmandatory MESSAGING semantics.

Station intent context is immutable at birth. Every child carries the same context; IN_APP is terminal-only and PUSH unfinished state is STATION_PENDING/STATION_SENDING. Database triggers reject ordinary/scenario siblings, missing parents, stripping/rebinding and ordinary PENDING/SENDING transitions. They do not acquire parent FOR UPDATE from a delivery trigger. Thus old workers cannot claim station rows on initial/retry/expired lease. Station claim generation is separate from provider attempt budget; pre-dispatch deferral may return an unused attempt but never reuse claim generation.

Fresh current owner eligibility has <=5s budget. Local identity, endpoint owner, ACTIVE endpoint/user/provider, exact platform/app/environment/credentials, runtime/rule/template and preferences are checked after lock waits using DB clock. FCM runtime→provider advisories precede delivery→endpoint→intent rows. No network occurs inside the transaction. Acknowledged exact durable pre-provider marker is required before one adapter call; marker readback never creates a new permission. FCM uses station-only one-shot HTTPS after token acquisition and withholds the ready TLS socket until the deadline check (ordinary FCM keeps fetch); APNs station calls wait for session connect then check before request creation, setting uncertainty before request; Web uses a station-only non-keepalive HTTPS agent with existing public-DNS validation and checks before handing a ready TLS socket to the queued request. Ordinary adapter defaults remain unchanged.

Definite circuit/auth refusal and APNs pre-submission failure use bounded existing retry policy, always STATION_PENDING. Proven station deadline refusal is generated only at the actual submission gate. Ambiguous network, malformed/unclassified response, marker ACK loss, provider ACK/local-finalization loss or expired dispatched lease never resends: terminal DEAD/STATION_PROVIDER_OUTCOME_UNKNOWN retains evidence. Aggregated429/5xx codes are conservatively UNKNOWN. Collapse/topic/APNs-ID is not provider idempotency. Late endpoint invalidation uses exact dispatched ciphertext/key/user/provider CAS.
