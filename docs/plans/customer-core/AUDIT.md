## Обязательные решения и соседний план

`lk2@80cdabb:docs/adr/0001-modular-monolith.md` фиксирует общий modular monolith; ADR 0002 — один writer на домен и Viva за адаптером; ADR 0004 — PadlHub UUID и tenant-level `VIVA/LOCAL`; ADR 0005/0008/0019/0023 — временные Viva delegation, route plan и Home. `ph-admin@fc6e470:docs/migration/viva-to-cup/README.md`, `canonical-model-and-ownership.md`, `inventory.md` уже составляют **проект** более широкой миграции. Он объявляет будущий canonical Client в ЦУП и свой UUID. Это расходится с данным заданием и действующими LK2 ADR 0001/0004: отдельный client ID разорвёт уже выданные UUID и consumer API. Минимальное решение: КЯ-01 оформляет identity ownership в LK2 с `identity.users.id` как client UUID; ЦУП становится авторизованным интерфейсом. До принятия решения не менять ph-admin план и не переносить его сроки/статус `STARTED` как доказательство готовности ядра. Открытые PR [#242](https://github.com/Z6v6e6r/lk2/pull/242) (проект телефонной аттестации) и [#244](https://github.com/Z6v6e6r/lk2/pull/244) (её реализация) уже работают с уникальным **подтверждённым login phone**; их не считать merged и не дублировать команды. Ревью #242 отвергло слияние аккаунтов по владению телефоном: для merge нужны доказательства обоих аккаунтов, отдельный проект и правила всех зависимых данных.

## Независимый read-only review

Security reviewer проверил проект identity/PII без правок и мутаций. Он нашёл опасные пробелы в recovery по общему контакту, step-up при привязке метода, отзыве сессий при reset, station object scope и несовместимости staff cookie ph-admin с текущей выдачей LK2 admin audience. Проект исправлен: [архитектура](ARCHITECTURE.md) задаёт независимое доказательство конкретного аккаунта, old-factor reauth, атомарный revoke, staff delegation и station visibility; [план приёмки](MIGRATION_AND_ACCEPTANCE.md) содержит отрицательные проверки и безопасный restore-контур. Ревью также уточнило, что normal login резолвит provider mapping, а не phone lookup. Это review **документа**, не подтверждение реализации этих защит. До КЯ-02/04/05 соответствующие API и rollout закрыты.
