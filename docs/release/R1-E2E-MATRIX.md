## Автоматизация G: что считать обязательным gate

1. Разделить deterministic unit/contract, physical PostgreSQL/Mongo/RabbitMQ и native/device suites. У каждой есть owner, exact source и fixture identity. Никаких production URLs по умолчанию.
2. Для required DB/broker suite отсутствие environment переменной должно дать failed required gate, а не green со skipped tests. Изменение этого поведения — отдельный scoped CI/test task, не часть аудита.
3. Для concurrency использовать несколько независимых соединений/processes и barriers; проверить persisted seats/ledger/outbox после завершения. Promise.all поверх mock недостаточно.
4. Для retry/offline инжектировать потерю ответа **после** durable write; сохранять original operation/idempotency key после app restart; запретить replacement POST до authoritative readback.
5. Для UI проверять результат пользователя, API receipt и persisted projection вместе. Для платежей отдельно provider transaction/entitlement evidence; для push separately accepted by provider / received by device / opened.
6. Общий полный R1 pass невозможен с пустыми Q05/Q08/Q09/Q10/Q13/Q14/Q18 native paths. Не компенсировать их количеством unit tests.

## Формат результата кейса

`case ID; repo SHA(s); run/attempt; build hash/version; environment + synthetic fixture ID; UTC time; command; passed/failed/skipped; assertions; receipt/correlation IDs; artifact URL/hash; provider write count; remaining gap`.

Секреты, телефоны, payment URLs, access/refresh tokens и реальные player records в Git/CI artifacts не помещать. Удалять PII из runtime receipts перед sharing; идентификаторы тестовых операций хранить в разрешённом evidence store.
