# Mobile native development

The checked-in `apps/mobile/ios` and `apps/mobile/android` directories are standard
Capacitor 8 projects. `apps/mobile/capacitor.config.ts` is the source of truth for the
application identifier, display name, web directory, and platform web-view settings.

## Safe preparation and verification

From the repository root, install the locked dependencies and prepare both projects:

```sh
npm ci
npm run mobile:native:prepare
npm run mobile:native:verify:test
npm run mobile:native:verify
```

`mobile:native:prepare` generates contract types, builds the production mobile web
bundle, and runs `cap sync` for iOS and Android. It does not run `cap add`, signing,
deployment, an IDE, an emulator, a simulator, or a live API flow. `cap add` is a
one-time bootstrap operation and must not be used for routine preparation.

To sync or build one platform explicitly:

```sh
npm run mobile:ios:sync
npm run mobile:android:sync
npm run mobile:android:build:debug
npm run mobile:ios:build:simulator
```

The Android command produces the standard debug build using the generated Gradle
wrapper; no repository signing configuration or release signing is involved. The iOS
command targets the generated `App.xcodeproj` and disables code signing; it requires a
full Xcode installation with an iOS Simulator SDK.

## Source-control boundary

Commit native source, Gradle wrapper metadata, Xcode project metadata, and the
standard placeholder icon/splash resources generated by Capacitor. Do not commit
copied web assets, generated Capacitor config, Gradle/build output, `local.properties`,
Pods, DerivedData, `xcuserdata`, signing files, provisioning profiles, certificates,
or machine-specific paths. The generated placeholder artwork is not approved
release branding and must be replaced only when an approved source asset is supplied.

This native shell intentionally contains no OAuth/deep-link handling, Universal/App
Links, session persistence, native API origin, push integration, device permissions,
repository-held signing credentials, release signing, or store publication workflow.
The standard Xcode project retains its generated automatic-signing metadata, while the
simulator build command explicitly disables signing. Android application backup is
disabled so WebView and cookie state cannot enter Auto Backup or device transfer.
