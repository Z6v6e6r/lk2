# Приёмка ЛК2 на lk2.padlhub.su

Ручная приёмка первой версии на контуре `https://lk2.padlhub.su` (tenant `local-padel`, данные
синтетические). Это единственный контур тестирования после вывода тестового стенда. Документ —
рабочий чек-лист тестировщика и владельца; факты состояния — в [STATUS](../STATUS.md).

Проверка read-only: приёмка не выполняет платежи, бронирования Viva, миграции и live-записи
провайдера. Коммерческая приёмка (CREATE60/JOIN60 по подписке) — отдельный сценарий
[`npm run lk2:commercial-acceptance`](../../scripts/lk2-commercial-acceptance.js), здесь она не
выполняется.

## 1. Предусловия (владелец/оператор)

Пока контур в режиме первой версии, каждый промоут на lk2 требует одобрения владельца (AGENTS.md,
«First-version mode»).

| Шаг               | Что сделать                                                                                                                                                                                                                                                | Критерий                                                                                                                                   |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Промоут веба      | На хосте: `deploy/timeweb/lk2-beta-lane.sh plan <green-main-sha>`, затем `promote <green-main-sha>` (на 2026-11-08 — `75110af8`)                                                                                                                           | `.well-known/assetlinks.json` на lk2 отдаёт оба сертификата: debug `22:07:BD…` и release `8C:59:A9…70:1E`; `npm run lk2:preflight` — READY |
| Тестовые аккаунты | Не нужны отдельные гранты: `games.test-courts` входит в beta-каталог `FULL_CLIENT_PERMISSIONS` (PR #617) и сохраняется при входе любого номера после промоута; для других контуров остаётся `npm run user:access:set`                                      | Вошедший номер видит каталог из двух кортов; контур без beta-флага или с выключенным `GAMES_TEST_COURTS_ENABLED` — нет                     |
| Тестовые корты    | `GAMES_TEST_COURTS_ENABLED=true` в `api.env` и `worker.env` (нужны `APP_ENV=staging`, `GAMES_COMMANDS_ENABLED=true`), затем пересоздание API/Worker через beta-lane; порядок — [lk2-beta-test-courts](lk2-beta-test-courts.md)                             | Создание/вход на тестовом корте разрешены, публичная карточка — 404                                                                        |
| Push              | `FCM_ENABLED=true`, `FCM_PROJECT_ID`, `FCM_APP_ID=ru.padlhub.app`, `FCM_CREDENTIAL_FILE=/run/phub/fcm-service-account.json`, bind `TIMEWEB_FCM_CREDENTIAL_SOURCE`; tenant-флаг `android_push_enabled`; порядок — [android-chats-fcm](android-chats-fcm.md) | Реальная доставка FCM на телефон подтверждена                                                                                              |
| APK               | Пользователь ставит подписанную сборку: `output/android-lk2-release-20261108-signed/PadlHub-1.13-code14-lk2-release-7a16312d.apk`                                                                                                                          | `adb shell pm get-app-links ru.padlhub.app` → `lk2.padlhub.su: verified`                                                                   |

Если FCM или доступ ещё не включены, соответствующие строки матрицы помечаются `BLOCKED`, а не
`PASS`: отсутствие проверки не считается успехом.

Состояние на 2026-11-08: промоуты `75110af8` → `10705588` (beta-каталог `games.test-courts`) →
`04d9c2f9` (уровневые ограничения #613; бэкапы `20261108T151721Z-75110af82795.dump`,
`20261108T175503Z-107055881e2f.dump`, `20261108T183903Z-04d9c2f9eb1b.dump`),
preflight = READY, FCM на сервере включён (`FCM_ENABLED=true`, tenant `android_push_enabled=true`),
`GAMES_TEST_COURTS_ENABLED=true` и `GAMES_COMMANDS_ENABLED=true` в api и worker. Право
`games.test-courts` входит в beta-каталог (PR #617) и выдаётся при входе любого номера начиная с
промоута `10705588`, поэтому строки 3–4 доступны для прогона без персональных грантов. На текущем
промоуте `04d9c2f9` также развёрнут уровневый гейт записи (#613); политика OFF по умолчанию.

## 2. Preflight (read-only, до и после промоута)

```sh
npm run lk2:preflight                      # человекочитаемый отчёт, exit 1 при FAIL
mkdir -p output/lk2-acceptance-$(date +%Y%m%d)
# --silent убирает баннер npm, иначе файл не является чистым JSON
npm run --silent lk2:preflight -- --json > output/lk2-acceptance-$(date +%Y%m%d)/preflight.json
```

Скрипт [`scripts/lk2-test-preflight.ts`](../../scripts/lk2-test-preflight.ts) проверяет только
публичные HTTPS-ответы и DNS: `/`, `/health/ready`, `/realtime/health/ready`,
`/.well-known/assetlinks.json` (сравнение с `apps/web/public/.well-known/assetlinks.json`),
`/android/oauth/yandex` (200, `no-store`, без `Location`, ссылка `padlhub://oauth/yandex`) и
A-запись из `deploy/timeweb/target.json`. Он не использует секреты и ничего не пишет.

Ожидаемый результат до промоута — ровно один FAIL `web.assetlinks` с отсутствующим release-сертификатом;
после промоута — `READY: 6 check(s) passed` (на 2026-11-08 READY). Любой другой FAIL — стоп и разбор, а
не начало тестов.

## 3. Установка и вход

```sh
adb uninstall ru.padlhub.app          # подпись release-ключа отличается от debug-сборок
adb install output/android-lk2-release-20261108-signed/PadlHub-1.13-code14-lk2-release-7a16312d.apk
adb shell pm get-app-links ru.padlhub.app
```

- Вход: **Войти с Яндекс ID** — штатный путь (нужен верифицированный App Link). Если ссылка не
  подтвердилась, статическая страница предложит **Открыть приложение** через `padlhub://oauth/yandex`;
  это резервный транспорт, а не отдельный вход.
- **Войти по СМС** — альтернатива для тестовых аккаунтов без Яндекс ID.
- Сессия должна переживать перезапуск приложения; выход и повторный вход — отдельные проверки.

## 5. Сбор доказательств

- Каталог: `output/lk2-acceptance-<YYYYMMDD>/`; имена файлов `<номер-сценария>-<шаг>.<png|txt>`.
- Preflight JSON (раздел 2) + вывод `pm get-app-links` + `adb logcat` для push.
- Уровни доказательств не смешивать: это `STAGING`-приёмка на синтетическом контуре lk2, не
  `PROVIDER` и не `PRODUCTION`. Локальные тесты и CI остаются `LOCAL`/`CI`.
- Завершённая приёмка = все строки `PASS` либо явно `BLOCKED` с причиной и владельцем.

## 6. Откат и очистка

- Приложение: `adb uninstall ru.padlhub.app`.
- Доступ к тестовым кортам: пока `BETA_FULL_CLIENT_ACCESS_ENABLED=true`, точечное удаление права
  `games.test-courts` вернётся при следующем входе, поэтому рабочие способы — `GAMES_TEST_COURTS_ENABLED=false`,
  выключение beta-флага или деактивация пользователя; уже выданное участие в играх это не отзывает.
- Тестовые корты: `GAMES_TEST_COURTS_ENABLED=false` закрывает новые создания/вход.
- Контур: `deploy/timeweb/lk2-beta-lane.sh rollback` возвращает предыдущий образ, схема остаётся;
  выполняется только с одобрения владельца.

## 7. Ограничения

- Автоматический E2E `stand:e2e`/`stand:e2e:results` работает только на mock-контуре
  (`VIVA_MODE=mock` + `AUTH_DEV_*`); эти ключи запрещены в runtime-контракте Timeweb, а
  `test.lk2.padlhub.su` выводится из работы. Приёмка на lk2 — ручная по разделу 4.
- Автоматическая веб-доставка на lk2 (`Standard Timeweb Web delivery`) сейчас падает на
  `BASELINE_ID_INVALID`; веб обновляется только beta-lane промоутом с одобрением владельца
  (`Follow-up finding`, не блокирует ручную приёмку).
- iOS, сторы и офлайн-подпись (PR #567) — после Android.
